# Test-only annual dues runtime — #742

This bounded staging integration consumes `membershipDuesCheckout`, `membershipDuesPayment` and `membershipAuthority`. It is isolated in `duesTestOnly.js`; neither legacy `index.js` nor `communityOnly.js` imports it. No provider connection or deployment is supplied. Existing member/event records remain compatible; no migration or roster import.

## Trust and transitions

Native callable Auth/App Check, matching caller/default tenant, recent verified token and current enabled/verified Auth metadata precede requests. The private `membershipTestParticipants/{uid}` marker must be current and synthetic; it is never a profile role. Exact staging or all three explicit loopback emulator hosts under a demo project, `COMMERCE_ENABLED=false` and `MPRC_TEST_DUES_ENABLED=true` are required. The frontend additionally needs its default-off staging flag. There is no production/live fallback.

Server offers fix 2500/3000 integer USD cents, LA calendar boundaries and a synthetic consent version/hash. No future term, automatic renewal or public external-payment instructions. One account lock and request-derived order ID are committed with immutable expectation, nonce, price, consent, expiration and provider idempotency key before any Checkout creation. Parallel commands/plans conflict; an exact request reuses byte-identical provider parameters. Unbound creation retries stop after five minutes, well within the provider's idempotency retention. Past that horizon the unresolved order stays held for private reconciliation; never guess that it is safe to charge again. Bound open Sessions are retrieved for resume. Verified empty expired Sessions may release the purchase lock; paid/held/pending orders cannot be discarded for a replacement purchase in the same year.

The adapter verifies the actual Stripe account for each operation, accepts only test credentials and objects, fixes Checkout URLs, and projects no customer/contact data. Raw signed webhook bodies are bounded and verified before a minimal durable event receipt. SDK retrieval checks Session, nonce/order/client reference, test realm, amount/currency and current PaymentIntent/Charge, including refunds/disputes before an older paid callback. Charge reversals resolve the exact Session with a bounded PaymentIntent query. Invalid or foreign observations grant nothing. Duplicate/out-of-order deliveries re-read current provider state and cannot regress an active/held term. Cancellation return is a read, never a payment or refund command.

Verified paid evidence, immutable term receipt, canonical `communityMemberships/{uid}` activation, optional private family root and transition audit are atomic. Changed revision/withdrawal/suspension/association, invalid current account/participant or an expired original term leaves durable paid-pending evidence. No silent rebase, renewal, unsuspension or refund. A defensive test reversal holds the order permanently and suspends only the authority still bound to that payment; it cannot revoke a later unrelated term. This is deliberately not real refund policy. Auth metadata is rechecked immediately before the transaction but cannot be atomically locked with Firestore; native distributed revocation guarantees are not claimed.

Server-only collections: `membershipTestOrders`, `membershipTestAccounts`, `membershipTestParticipants`, `membershipTestTerms`, `membershipTestFamilies`, `membershipTestEvents`, `membershipTestAudit`, `membershipTestLimits`. Existing default-deny Rules are unchanged; denial regressions cover anonymous/member/admin reads and admin create/update/delete. No claims, mail, scheduled worker, dependency, payment-method storage or direct browser database access. Checkout URLs exist only in an immediate response and navigation, never saved records/logs. All outward errors are fixed and redacted.

Actual sandbox/live evidence, provider changes, real policy approval and production rollout remain separate.

Local tests use transactional doubles and the installed SDK's real signature verifier, with no outside network. Hosted Node22 CI runs `testMembershipDues.emulator.test.js` under native Firestore/Auth emulators and a synthetic provider: it proves native order/activation races and free-event admission, not Stripe API behavior. Frontend tests cover consent, account/session fences, unknown responses, expiry without polling, saved retry/reload and verified test URL navigation.
